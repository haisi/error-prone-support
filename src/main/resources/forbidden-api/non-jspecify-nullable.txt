# non-jspecify-nullable: nullability annotations from libraries other than jSpecify
# (https://jspecify.dev). Use org.jspecify.annotations.Nullable / NonNull / NullMarked /
# NullUnmarked instead - jSpecify is the vendor-neutral standard that JDT, Checker Framework,
# IntelliJ, Error Prone's NullAway and others all recognize, so mixing it with any of the
# annotations below just fragments a codebase's nullability story across incompatible types.

# JSR-305 (javax.annotation.*) - abandoned as a JSR, but still widely used via the
# com.google.code.findbugs:jsr305 jar.
javax.annotation.Nullable @ Use org.jspecify.annotations.Nullable instead
javax.annotation.Nonnull @ Use org.jspecify.annotations.NonNull instead
javax.annotation.CheckForNull @ Use org.jspecify.annotations.Nullable instead

# Spring Framework
org.springframework.lang.Nullable @ Use org.jspecify.annotations.Nullable instead
org.springframework.lang.NonNull @ Use org.jspecify.annotations.NonNull instead
org.springframework.lang.NonNullApi @ Use org.jspecify.annotations.NullMarked instead
org.springframework.lang.NonNullFields @ Use org.jspecify.annotations.NullMarked instead

# Micrometer

org.checkerframework.checker.nullness.qual.MonotonicNonNull @ Use org.jspecify.annotations.Nullable instead, and stabilize the flow-sensitive guarantee in code rather than in the type
